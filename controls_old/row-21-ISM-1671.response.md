# Microsoft Office macros are disabled for users that do not have a demonstrated business requirement. (ISM-1671)

## Summary

Microsoft Office macros are disabled by default to reduce macro-based threats.[^1] Enforce macro suppression via Intune by blocking macros across all Office apps, with exceptions only for users who have a demonstrated business need.[^1][^2] To allow exceptions, create a dedicated group (Allow macro execution - Trusted Publisher) and apply an All Macros Disabled policy to All Office Users, excluding the Trusted Publisher group via policy separation.[^1] This approach aligns with ACSC hardening guidance and the Intune security baseline for Office settings.[^2]

## Design Decision

> [!NOTE] Disable all Microsoft Office macros via Intune by default and permit execution only for approved users using a dedicated exemption group for macros signed by a Trusted Publisher.

  8. Ability to create and assign an All Office Users group for policy assignments. [^1]

## Implementation Steps

### Disable all Office macros via Intune

#### Stage 1: To create the policy to target desired users

1. Create a policy to contain users that are targeted with the Office apps and the Office hardening policies. This group is referred to as **All Office Users**.
2. Create the Microsoft 365 Apps for Windows 10 or later app, under **Apps > Windows > Add > Microsoft 365 Apps**.
3. Include the Microsoft 365 Apps as required by your organization.
4. Set the architecture to: **64-bit** (recommended).
5. Set the Update Channel to: **Semi-Annual Enterprise Channel** (recommended).

#### Stage 2: To import the ACSC hardening guideline policy

1. Save the ACSC Office Hardening Guidelines policy to your local device:  
   [ACSC Office Hardening Guidelines.json](https://github.com/microsoft/Intune-ACSC-Windows-Hardening-Guidelines/blob/main/office/policies/ACSC%20Office%20Hardening%20Guidelines.json)  
   (Not provided in source documentation for other formats.)
2. Navigate to the Microsoft Intune console.
3. Import a policy, under Devices > Windows > Configuration profiles > Create > Import Policy.
4. Name the policy, select Browse for files under Policy file and navigate to the saved policy from step 1.
5. Select Save.

##### Import script to prevent activation of Object Linking and Embedding packages

1. Navigate to **Devices > Scripts** and create a new PowerShell script.
2. Import the PowerShell script to prevent activation of Object Linking and Embedding packages:  
   [OfficeMacroHardening-PreventActivationofOLE.ps1](https://github.com/microsoft/Intune-ACSC-Windows-Hardening-Guidelines/blob/main/office/scripts/OfficeMacroHardening-PreventActivationofOLE.ps1)
3. Run this script using the logged on credentials: **Yes**.
4. Enforce script signature check: **No**.
5. Run script in 64-bit PowerShell Host: **No**.
6. Assign the PowerShell script to: **All Office Users** (created in Stage 1).

#### Stage 3: Creation of the policy set combining Microsoft 365 Apps and ACSC Hardening Guideline policy

1. Navigate to **Devices > Policy sets > Create**.
2. Under **Application Management > Apps**, select **Microsoft 365 Apps (for Windows 10 and later)** (created in Stage 1).
3. Under **Device Management > Device Configuration Profiles**, select **ACSC Office Hardening** (created in Stage 2).
4. Under Assignments select **All Office Users** (created in Stage 1).
5. Import the Endpoint Security Attack Surface Reduction policy.
6. Navigate to Graph Explorer and authenticate.
7. Create a POST request, using the beta schema to the Attack Surface Reduction policy endpoint:  
   https://graph.microsoft.com/beta/deviceManagement/templates/0e237410-1367-4844-bd7f-15fb0f08943b/createInstance
8. Copy the JSON in the [ACSC Windows Hardening Guidelines-Attack Surface Reduction.json](https://github.com/microsoft/Intune-ACSC-Windows-Hardening-Guidelines/blob/main/policies/ACSC%20Windows%20Hardening%20Guidelines-Attack%20Surface%20Reduction.json) and paste it in the request body.
9. (Optional) modify the name value if necessary.
10. Assign the policy to: **All Office Users** (created in Stage 1).

> Note: This Attack Surface Reduction (ASR) policy configures each of the ASR rules recommended by the ACSC in audit mode. ASR rules should be tested for compatibility issues in any environment before enforcement.

#### Controlling macro execution (implementation detail)

- Create a group that contains users that are able to run Office macros if they're signed by a Trusted Publisher. This group is referred to as: **Allow macro execution - Trusted Publisher**.
- Save the [Macros Enabled for Trusted Publishers policy](https://github.com/microsoft/Intune-ACSC-Windows-Hardening-Guidelines/blob/main/office/policies/Macros%20Enabled%20for%20Trusted%20Publishers.json) to your local device.
- Navigate to the Microsoft Intune console.
- Import a policy, under Devices > Windows > Configuration profiles > Create > Import Policy.
- Name the policy, select Browse for files under Policy file and navigate to the saved policy (from step 2).
- Select Save.
- Assign the policy to the group: **Allow macro execution - Trusted Publisher**.

- Exclude the **Allow macro execution - Trusted Publisher** group from the All Macros Disabled policy.

- By default, target all Office users with a policy that blocks macro execution. The following additional mitigations apply when the Trusted Publisher exception is in place (per source content):

  - Microsoft Office macros are disabled for users without a demonstrated business requirement. (Block macros for All Office Users)
  - For signing and trusted publishers, the ASR and Defender policies provide logging and protection when macros are used by trusted publishers.

- Importing and applying the All Macros Disabled policy:

  - Save the [All Macros Disabled.json policy](https://github.com/microsoft/Intune-ACSC-Windows-Hardening-Guidelines/blob/main/office/policies/All%20Macros%20Disabled.json) to your local device.
  - Navigate to the Microsoft Intune console.
  - Import a policy, under Devices > Windows > Configuration profiles > Create > Import Policy.
  - Name the policy, select Browse for files under Policy file and navigate to the saved policy (from step 1).
  - Select Save.
  - Assign the All Macros Disabled policy to **All Office Users** (that was created at the start of this document).
  - Exclude the **Allow macro execution - Trusted Publisher** group (from step 1).

- The recommended defaults and controls to support this model are described in the ASCS hardening guidance.
