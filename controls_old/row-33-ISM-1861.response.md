## Summary

LSA protection isolates the LSASS process to protect credentials from untrusted code and memory access.[^1] Enable added LSA protection via Intune by creating a custom device configuration profile that sets the OMA-URI value to configure LSA protection (./Device/Vendor/MSFT/Policy/Config/LocalSecurityAuthority/ConfigureLsaProtectedProcess) with an Integer of 1 (with UEFI lock) or 2 (without), then restart; alternatively, enable via registry or Local Group Policy as described in the Microsoft guidance.[^1]

## Design Decision

> [!NOTE] Enable LSA protection via Intune registry settings or security baseline to ensure LSASS runs as a protected process on eligible devices.

## Prerequisites

* **Licensing:** Not provided in source documentation. [^1]
* **Permissions/Roles:** Not provided in source documentation. [^1]
* **Dependencies:** Windows 11 version 22H2 or later; devices enterprise joined; devices capable of Hypervisor-protected Code Integrity (HVCI); access to Intune admin center for custom device configuration profiles; access to Group Policy Management Console (GPMC). [^1]

## Implementation Steps

### Enable LSA protection via Intune custom device configuration profile

1. In the Intune admin center, go to Devices > Windows > Configuration profiles, and then select Create profile.
2. On the Create a profile screen, select Platform: Windows 10 and later.
3. For Profile type, select Templates, and then Custom, and then select Create.
4. On the Basics screen, enter a name and optional description for the profile, and then select Next.
5. On the Configuration settings screen, select Add.
6. On the Add row screen, enter the following:
   - Name: Open Mobile Alliance – Uniform Resource Identifier (OMA-URI) setting
   - OMA-URI: ./Device/Vendor/MSFT/Policy/Config/LocalSecurityAuthority/ConfigureLsaProtectedProcess
   - Data type: Integer
   - Value: enter 1 to configure LSASS to run as a protected process with a UEFI lock, or enter 2 to configure LSASS to run as a protected process without a UEFI variable
   - Note: For more information about this policy CSP, see LocalSecurityAuthority - ConfigureLsaProtectedProcess.
     See https://go.microsoft.com/fwlink/?linkid=2067233 for related policy guidance. [^1]
7. Select Save, and then select Next.
8. On the Assignments page, configure the assignments, and then select Next.
9. On the Review + create page, verify the configuration, and then select Create.
10. Restart the computer.

### Verify LSA protection

1. Open Event Viewer.
2. Expand Windows Logs > System.
3. Look for the WinInit event: 12: LSASS.exe was started as a protected process with level: 4.
