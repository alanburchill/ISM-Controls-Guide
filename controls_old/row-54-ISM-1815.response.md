## Summary

Event logs are protected from unauthorised modification and deletion[^1]. Use RBAC in Microsoft Defender XDR Unified RBAC and Microsoft Sentinel to protect event logs from tampering[^3]. Centralized log management and unified RBAC enable controlled access across logging and monitoring workflows to support cross-domain threat detection[^1].

## Design Decision

> [!NOTE] Implement Unified RBAC in Defender XDR and Sentinel to restrict access to event logs and log-management actions, ensuring event logs are protected from unauthorized modification and deletion.

## Prerequisites

* **Licensing:** Not provided in source documentation. [^1]

* **Permissions/Roles:** Global Administrator or Security Administrator in Microsoft Entra ID is required to access Permissions and Roles in the Defender portal; to create custom roles, Authorization permissions are required, and for Sentinel data lake-related roles, a Log Analytics workspace must be enabled for Microsoft Sentinel and onboarded to the Defender portal. [^3][^2]

* **Dependencies:** Activation of the Defender XDR Unified RBAC model is required to use Unified RBAC; for custom roles that involve Sentinel data lake, a Log Analytics workspace must be enabled and Sentinel must be onboarded to Defender portal. [^3][^2]

## Implementation Steps

### RBAC-based protection of event logs in Defender XDR and Sentinel

1. Activate the Defender XDR Unified RBAC model for workloads.
   - Enable the Unified RBAC model to govern permissions across Defender XDR experiences and Sentinel data access.[^3]

2. Create a custom RBAC role for log access and tamper protection.
   1. Sign in to the Defender portal.
   2. In the navigation pane, select Permissions > Roles > Create custom role.
   3. On Basics, enter the role name and an optional description, then select Next.
   4. On Choose permissions, select the following:
      - Security operations
      - Security posture
      - Authorization and settings
      - Data Operations (Preview)
   5. When you open Authorization and settings, adjust permissions as needed, then select Apply.
   6. Proceed to assign users and data sources.  
   This follows the documented wizard steps for creating custom roles.[^4]

3. Assign users and data sources to the new role.
   1. On the Assign users and data sources page, choose Add assignment.
   2. Provide an Assignment name, select Microsoft Entra security groups or individual users, and pick the Data sources to grant access.  
   3. (Optional) Enable Include future data sources automatically to grant access to new data sources automatically.
   4. Save the assignment.  
   These steps align with the role-creation workflow for linking access to specific data sources.[^4]

4. Create an Authorization-only role for managing roles and permissions.
   1. Sign in to the Defender portal as Global Administrator or Security Administrator.
   2. Navigate Permissions > Roles > Create custom role.
   3. Enter the role name and description, then Next.
   4. On Authorization and settings, choose the appropriate permission scope (e.g., Select all permissions or Read-only) and continue.
   5. Add assignments specifying data sources and assign users/groups.
   6. Review and Submit to create the role.
   This mirrors the dedicated authorization-role workflow described in the Defender XDR RBAC guidance.[^4]

5. Review activation and enforce RBAC across Defender XDR and Sentinel.
   - Activate the Defender XDR Unified RBAC model for the relevant workloads, then review role assignments in the Defender portal to confirm they reflect the configured permissions. See the RBAC management guidance for details.[^3]
