# Microsoft Office macros are blocked from making Win32 API calls. (ISM-1673)

## Summary

The Attack Surface Reduction rule Block Win32 API calls from Office macros blocks Office macros from calling Win32 APIs, reducing macro-based exploits.[^1] Enable this rule via Intune by creating or updating an Endpoint security Attack surface reduction policy and setting the Block Win32 API calls from Office macros state to Block.[^1][^2] Defender baseline configurations also include this rule with a default state of Block, ensuring protection even without custom policy.[^3]

## Design Decision

> [!NOTE] Enable the ASR rule to block Win32 API calls from Office macros via Intune. This centralizes enforcement of macro security in line with the guidance.

## Prerequisites

* **Licensing:** Enterprise Windows license with Defender for Endpoint; full ASR rules require an enterprise license; Microsoft 365 E5 recommended. [^2]
* **Permissions/Roles:** Not provided in source documentation. [^1]
* **Dependencies:** Intune endpoint security Attack Surface Reduction profile; Windows devices managed via Intune are supported. [^1]

## Implementation Steps

### Enable Block Win32 API calls from Office macros via Intune Attack Surface Reduction rules

1. Prerequisites: Ensure Defender for Endpoint ASR prerequisites are met for full ASR functionality. See source for details.[^2]
2. In the Microsoft Intune admin center, navigate to: Endpoint security > Attack surface reduction.[^1]
3. Create a policy (or edit an existing one). For Profile type, select Attack surface reduction rules.[^1]
4. In Configuration settings, open Attack Surface Reduction and enable the setting Block Win32 API calls from Office macro.[^1]
5. Save the policy and assign it to the required device groups or users.[^1]
6. Verification: On a managed device, verify the policy is applied by listing Defender preferences. Run: `Get-MpPreference` and confirm the ASR Block Win32 API calls from Office macro rule is enabled.[^2]
7. If using a CSP-based approach instead of Intune configuration, configure via Defender Attack Surface Reduction Rules CSP and set the rule GUID 92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7B to Block (Enabled). See CSP reference.[^4]
8. Example PowerShell reference (demonstration): enable the rule via PowerShell as a reference implementation.

```powershell
# Example: Enable Block for Win32 API calls from Office macros (ASR)
Add-MpPreference -AttackSurfaceReductionRules_Ids 92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7B -AttackSurfaceReductionRules_Actions Enabled
```

9. Note: The ASR rule is part of the Defender for Endpoint ASR rules. See demonstrations for additional context and scenarios.[^5]
