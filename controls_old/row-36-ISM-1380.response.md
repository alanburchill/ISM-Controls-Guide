## Summary

Deploy a Conditional Access policy that blocks cloud administrators unless they sign in from a trusted known IP address range.[^1] Plan the deployment by defining the if-then conditions (users/workloads, apps, devices, locations) and apply a strict block control, testing the policy in a pilot before organization-wide rollout.[^1] Exclude emergency access accounts from the policy to prevent lockout during rollout or misconfigurations.[^1]

## Design Decision

> [!NOTE] Implement a Conditional Access policy that blocks cloud administrators unless sign-ins originate from a trusted known IP address range. Use named locations in Microsoft Entra ID to define the allowed IP ranges and enforce sign-in restrictions accordingly.

* **Dependencies:** Communicate changes to affected users and provide supporting documentation; verify emergency access accounts are excluded from all policies; test policies with a pilot group before organization-wide rollout; ensure users have registered required authentication methods. [^1]

## Implementation Steps

### Deploy Conditional Access Policy to block cloud administrators from untrusted IP ranges

1. Identify trusted known IP address ranges that will be allowed for cloud administrator access. Document these ranges. [^1]

2. In the Microsoft Entra admin center, create Named locations for each trusted IP range. These named locations will be used as policy conditions to recognize trusted networks. [^1]

3. Create a Conditional Access policy with the following configuration:
   - Include: cloud administrator accounts or a group/role that represents cloud admins. [^1]
   - Conditions: Locations -> Include: Named locations for trusted IPs. [^1]
   - Access controls: Grant control -> Block access. [^1]
   - Policy mode: Test with a pilot group or in a limited scope before organization-wide rollout. [^1]

4. Validate impact and adjust:
   - Review sign-in logs to confirm trusted IPs continue to access resources while untrusted IPs are blocked. [^1]
   - Use policy impact or report-only results to understand potential effects before enabling enforcement. [^1]

5. Roll out:
   - Enable the policy organization-wide after successful testing. Monitor for issues and adjust named locations as needed. [^1]
