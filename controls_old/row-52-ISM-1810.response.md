## Summary

Backups of data, applications and settings must be synchronized to enable restoration to a common point in time.[^1] Use Azure Backup to take application-consistent snapshots for synchronised restore points.[^2] Windows VMs use VSS to achieve application-consistent snapshots, while Linux VMs rely on pre- and post-scripts to achieve app consistency.[^1]

## Design Decision

> [!NOTE] Use Azure Backup to take application-consistent snapshots for synchronised restore points.

## Prerequisites

* **Licensing:** Not provided in source documentation. [^3]
* **Permissions/Roles:** The Backup Vault uses a managed identity to access Azure resources. To configure backup of a managed disk and restore from past backups, the Vault's managed identity requires permissions on the source disk, the snapshot resource group where snapshots are created and managed, and the target resource group where you want to restore the backup. Grant these permissions using Azure RBAC. [^3]
* **Dependencies:** Requires a Backup vault (Recovery Services vault) to configure backups. The vault uses a managed identity to access resources and requires the permissions described above. [^2]

## Implementation Steps

### Use Azure Backup for application-consistent VM restore points

1. Create or select a Recovery Services vault and create/attach a VM backup policy that enables application-consistent snapshots. VM restore points are organized into restore point collections. [^1][^2]

2. For Windows VMs, ensure the VM is eligible for VSS-based app-consistent snapshots. Azure Backup coordinates with VSS to take the app-consistent snapshot. [^2]

3. For Linux VMs, configure pre- and post-scripts to enable application-consistent backups. Azure Backup invokes these scripts to create application-consistent snapshots. [^2]

4. Ensure the backup extension is installed on Windows VMs to coordinate the snapshot process during backups. [^2]

5. Start or wait for the backup to run according to the policy schedule; the backup job takes the app-consistent snapshot and transfers the data to the Recovery Services vault. [^2]

6. Verify that the created restore point is application-consistent across all attached disks. This ensures reliable restoration. [^2][^1]

7. If needed, use restore point collections to manage synchronized restores across multiple VMs. [^1]
