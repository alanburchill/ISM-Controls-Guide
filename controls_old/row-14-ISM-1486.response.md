## Summary

Hardens user applications by ensuring Java is not installed and by using a browser that does not support Java applets, thereby preventing Java from processing internet-based content[^1]. Java isn't installed by default on Windows 10/11, reducing exposure to Java applets[^1]. Implementations rely on ACSC Edge Hardening Guidelines and Edge Baselines to configure browser settings that block Java applets and related vectors[^1].

## Design Decision

> [!NOTE] Do not install Java. Configure Microsoft Edge as the primary browser since Edge does not support Java applets. Enable Internet Explorer mode in Edge for legacy sites as needed to maintain compatibility.

## Implementation Steps

### Web browser hardening using Microsoft Edge baseline and ACSC Edge Hardening Guidelines

Java isn't installed by default on Windows 10/11. Implement Edge baseline and import ACSC Edge Harden Guidelines to reinforce browser hardening.

1. Deploy Microsoft Edge Baseline:
   1. Navigate to Endpoint Security > Security Baselines > Microsoft Edge Baseline.
   2. Create a new Microsoft Edge Baseline by selecting Create Profile.
   3. Review the configuration, and assign the Security Baseline to a group. [^1]

2. Implement ACSC Edge Hardening Guidelines:
   1. Save the ACSC Microsoft Edge Hardening Guidelines policy to your local device. See the ACSC Edge Hardening Guidelines policy in the repository. [^1]
   2. Navigate to the Microsoft Intune console.
   3. Import a policy, under Devices > Windows > Configuration profiles > Create > Import Policy
   4. Name the policy, select Browse for files under Policy file and navigate to the saved policy from step 1.
   5. Save. [^1]

3. Optional: Remove legacy components to reduce exposure to Java applets:
   1. Add [UserApplicationHardening-RemoveFeatures.ps1](https://github.com/microsoft/Intune-ACSC-Windows-Hardening-Guidelines/blob/main/scripts/UserApplicationHardening-RemoveFeatures.ps1) as a PowerShell script with the following options:
      - Run this script using the logged on credentials: No
      - Enforce script signature check: No
      - Run script in 64-bit PowerShell Host: No
   2. Assign the script to a deployment group. [^1]
