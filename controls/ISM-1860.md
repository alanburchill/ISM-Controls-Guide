## Summary

PDF hardening for user applications enforces ASD and vendor guidance, with the most restrictive controls taking precedence when conflicts occur, and is implemented by applying vendor PDF hardening settings via Intune configuration profiles to standardize protection across endpoints.[^1][^3]

### Justification

- **CVE-2016-3198**: Microsoft Edge security feature bypass where CSP validation can be bypassed by specially crafted documents, potentially enabling malicious content to execute.[^4]

- **CVE-2016-3203**: Windows PDF Remote Code Execution vulnerability triggered when a user opens a specially crafted PDF file, allowing arbitrary code execution.[^5]

## Design Decision

> [!NOTE]
> The **vendor PDF hardening settings** will be applied via **Intune configuration profiles** to enforce the vendor guidance for PDF hardening. In case of conflicts with ASD guidance, the most restrictive guidance will be applied.

## Implementation Steps

### Intune Attack Surface Reduction policy for PDF hardening

1. In Intune, navigate to **Endpoint Security > Attack Surface Reduction**.[^1]
2. Create (or modify) a new **Attack Surface Reduction Endpoint Security Policy**.[^1]
3. Set **Block Adobe Reader from creating child processes** to Enable.[^1]
4. Assign the Attack Surface Reduction Rule policy to a group.[^1]
