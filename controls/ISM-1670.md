## Summary

Configure the **Block Adobe Reader from creating child processes** ASR rule via **Intune** and deploy **ScriptName.ps1** using **Intune deployment**.[^1][^2]

[^1]: [Essential Eight user application hardening](https://learn.microsoft.com/en-us/compliance/anz/e8-app-harden)
[^2]: [Intune endpoint security Attack surface reduction settings](https://learn.microsoft.com/en-us/intune/intune-service/protect/endpoint-security-asr-profile-settings)

## Design Decision

Use **Intune** to (1) configure **Block Adobe Reader from creating child processes** and (2) deploy **ScriptName.ps1** via **Intune policy deployment**.

> [!NOTE]
> Deploying **ScriptName.ps1** also disables **Other Feature**.

## Prerequisites

- **Licensing:** Microsoft Intune Plan 1 licensing at minimum if Intune is used to configure devices.[^1]
- **Permissions/Roles:** Access to Microsoft Intune to create and modify **Attack Surface Reduction** policies in Endpoint Security; ability to assign the policy to a group.[^1]

[^1]: [Essential Eight user application hardening - Essential Eight](https://learn.microsoft.com/en-us/compliance/anz/e8-app-harden)

## Implementation Steps

### Enable ASR Rule to Block Adobe Reader from Creating Child Processes using Intune

1. In Intune, navigate to **Endpoint Security** > **Attack Surface Reduction**. [^1]

2. Create (or modify) a new **Attack Surface Reduction Endpoint Security Policy**. [^1]

3. In the policy, locate the setting **Block Adobe Reader from creating child processes** and set it to **Enable**. [^2]

4. Assign the policy to a group. [^1]

| Setting | Value |
| ------- | ----- |
| **Block Adobe Reader from creating child processes** | **Enable** |

> [!NOTE]
> The ASR rule is used to block Adobe Reader from creating child processes as part of hardening user applications.[^1]
