## Summary

Patches, updates, or mitigations for vulnerabilities in applications other than office productivity suites, web browsers and their extensions, email clients, PDF software, and security products are applied within one month of release using Intune-based deployment methods.[^2] For third-party applications, deploy new versions via the Intune Enterprise Application Catalogue; otherwise repackage and redeploy all applications that require security updates within the timeline.[^2] Windows patching is managed through Windows Update for Business with update rings defined via Intune, enabling controlled deployment aligned with organizational needs.[^3]

[^2]: [Patch applications](https://learn.microsoft.com/en-us/compliance/anz/e8-patch-app#patch-applications)
[^3]: [ASD Blueprint: Windows update and patching](https://blueprint.asd.gov.au/design/endpoints/windows/configuration/windows-update-and-patching/)

## Design Decision

> [!NOTE] Configure and enable Windows Autopatch for all workstations via the InTune admin portal; deploy third-party app patches via the Intune Enterprise Application Catalogue; set Edge to "Targe Channel" or "Stable".

## Prerequisites

* **Dependencies:** 
  1. Microsoft Intune required for patch deployment workflows. [^1]
  2. Windows Update for Business referenced for patch management strategies. [^3]
  3. Microsoft Endpoint Configuration Manager (MECM) and Windows Server Update Services (WSUS) as alternative patching technologies. [^3]
