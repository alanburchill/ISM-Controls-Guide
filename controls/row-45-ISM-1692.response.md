## Summary

Configure **Windows Autopatch** for all workstations via the **Intune** admin portal and deploy third-party application patches through the **Intune Enterprise Application Catalogue**.[^1] If patches cannot be delivered through the catalogue, repackage and redeploy all applications requiring security updates within the defined timeline, and configure **Microsoft Edge** on all devices to use **Target Channel** or **Stable**.[^1]

[^1]: [Essential Eight patch applications - Essential Eight | Microsoft Learn](https://learn.microsoft.com/en-us/compliance/anz/e8-patch-app)

## Design Decision

Use **Windows Autopatch** to configure and enable patching for all workstations via **Intune**, deploy third-party app updates via **Intune Enterprise Application Catalogue**, and configure **Edge** to **Target Channel** or **Stable**.

> [!NOTE]
> This design uses **Windows Autopatch** with **Intune** for patching, **Intune Enterprise Application Catalogue** for third-party updates, and **Edge** channel settings **Target Channel** or **Stable**.

## Prerequisites

### Permissions/Roles

- Admins with the fewest permissions necessary are recommended for Windows Autopatch enrollment; avoid broad Global Administrator roles where possible.[^2]
- Admin contacts must be defined for each area of focus in Intune as part of enrollment preparations.[^2]

### Dependencies

- Intune and Microsoft Entra ID must be configured to support Windows Autopatch enrollment; a readiness assessment checks these settings.[^2]
- IT administration must identify devices and add them to the Windows Autopatch Device Registration group; devices must pass readiness checks prior to enrollment.[^2]
- Endpoints must be onboarded to Microsoft Defender for Endpoint before remediation workflows can be used.[^1]
- Intune Windows Update for Business is used for patching; for cloud native deployments, Intune is the required patching technology (Intune is the only option in cloud native deployments).\[^3]

## Implementation Steps

### Enable Windows Autopatch Enrollment for all workstations via Intune

1. As a Global Administrator, enable **Windows Autopatch** enrollment in the Intune portal: Windows Autopatch > Tenant enrollment.[^2]

2. Run the **Readiness assessment** to verify Intune and Entra ID settings for Windows Autopatch deployment.[^2]

3. Add admin contacts for Windows Autopatch in Intune: sign in to Intune, navigate to Windows Autopatch > Admin contacts, select Add, and enter name, email, phone, and language; assigns areas of focus; Save.[^2]

4. Register devices for Windows Autopatch by identifying eligible devices, adding them to the Windows Autopatch Device Registration group, and completing readiness checks to enable deployment.[^2]

### Deploy third-party applications updates via Intune Application Deployment Method

1. Use the **Intune application deployment method** to deploy new versions of third-party applications within 48 hours of release.[^1]

### Configure Edge browser to Target Channel or Stable

1. Create an **Update Ring** policy in Intune to govern Windows Update for Business settings, including Edge updates. Update rings define how and when updates are deployed to devices.[^3]

2. Configure the Edge channel to **Target Channel** or **Stable** per organizational requirements.[^3]

3. Assign the update ring policy to the appropriate device groups (e.g., all Windows devices).[^3]
