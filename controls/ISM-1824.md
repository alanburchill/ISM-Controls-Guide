## Summary

Configure **Lock PDF security settings** via **Intune** and deploy **LockPdfSettings.ps1** using **Intune policy deployment**.[^1][^2]

[^1]: [Essential Eight user application hardening - Essential Eight](https://learn.microsoft.com/en-us/compliance/anz/e8-app-harden)
[^2]: [ASD Blueprint: User application hardening](https://blueprint.asd.gov.au/security-and-governance/essential-eight/user-application-hardening/)

## Design Decision

Use **Intune** to (1) configure **PDF security settings** and (2) deploy **LockPDFSettings.ps1** via **Intune**.

> [!NOTE]
> Deploying **LockPDFSettings.ps1** also disables user ability to modify PDF security settings.

## Prerequisites

* **Permissions/Roles:** Access to **Microsoft Intune** to create and deploy an **Attack Surface Reduction** policy and assign it to a group.[^1]

[^1]: [Essential Eight user application hardening](https://learn.microsoft.com/en-us/compliance/anz/e8-app-harden)

## Implementation Steps

### Configure Attack Surface Reduction Policy in Intune

1. In Intune, navigate to **Endpoint Security** > **Attack Surface Reduction**.[^1]
2. Create (or modify) a new **Attack Surface Reduction Endpoint Security Policy**.[^1]
3. Set **Block Adobe Reader from creating child processes** to Enable.[^1]
4. Assign the Attack Surface Reduction Policy to a group.[^1]
