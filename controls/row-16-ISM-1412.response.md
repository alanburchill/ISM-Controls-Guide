## Summary

Deploy the ACSC Edge hardening configuration through Microsoft Intune to harden web browsers in accordance with ACSC guidance. Import the ACSC Edge Hardening Guidelines policy into Intune and apply the Microsoft Edge Security Baseline to targeted devices. Deploy Edge hardening concurrently with the Edge Baseline as part of the Essential Eight user application hardening approach.

## Implementation Steps

### Deploy ACSC Edge Hardening via Intune

1. Save the ACSC Edge hardening JSON policy to the local device. This is the policy file containing Edge hardening guidance to import into Intune.  
   Source: ACSC Edge hardening JSON policy reference. [^1]

2. Open the Microsoft Intune admin center.  
   Navigate to deploy Edge hardening via Intune.  
   Source: Deploy Microsoft Edge security baseline guidance. [^2]

3. Import the policy into Intune.  
   - Go to Devices > Windows > Configuration profiles > Create > Import Policy.  
   - Name the policy and browse to the saved policy file from step 1.  
   - Save the policy.  
   This process aligns with importing the ACSC Edge hardening policy into Intune. [^1][^2]

4. Review and assign the security baseline.  
   - Review the imported configuration.  
   - Assign the Security Baseline to a group.  
   Source guidance: Edge hardening deployment workflow. [^1]

5. Deploy the Microsoft Edge security baseline.  
   - In the Intune admin center, navigate to Endpoint security > Security baselines > Security Baseline for Microsoft Edge > Create policy > Create.  
   - Proceed to the next steps. Source: Edge baseline deployment steps. [^2]

6. Configure the Edge baseline (Basics tab).  
   - Name: Microsoft Edge Security Baseline - Level 2.  
   - Description: Microsoft Edge security baseline providing Level 2 enhanced security.  
   Source: Baseline creation details. [^2]

7. Review and apply preconfigured Edge settings.  
   - In Configuration settings, expand Microsoft Edge and review the following preconfigured settings:  
     - Allow unconfigured sites to be reloaded in Internet Explorer mode — Disabled.  
     - Allow users to proceed from the HTTPS warning page — Disabled.  
     - Automatically open downloaded MHT or MHTML files from the web in Internet Explorer mode — Disabled.  
     - Dynamic Code Settings — Enabled.  
     - Dynamic Code Settings (Device) — Default dynamic code settings.  
     - Enable Application Bound Encryption — Enabled.  
     - Enable browser legacy extension point blocking — Enabled.  
     - Enable site isolation for every site — Enabled.  
     - Show the Reload in Internet Explorer mode button in the toolbar — Disabled.  
     - Specifies whether SharedArrayBuffers can be used in a non cross-origin-isolated context — Disabled.  
     - Extensions: Control which extensions cannot be installed — Enabled.  
     - Extension IDs the user should be prevented from installing — *.  
   Source: Microsoft Edge security baseline configuration details. [^2]

8. Save and assign the Edge security baseline.  
   - Save the configuration and assign it to the desired group.  
   Source: Baseline save/assignment process. [^1]

9. Optional: augment Edge hardening with additional policies.  
   - Consider applying per-site configuration and related policies as described in Edge management guidance.  
   - Example policy: Disable lockdown of Start pages (as applicable in your environment).  
   Sources: Per-site configuration by policy and related Edge browser policy guidance. [^4][^5]

10. Reference and verify remote policy sources.  
    - ACSC Edge hardening guidelines JSON is maintained remotely and should be kept up to date as part of the baseline.  
    Sources: ACSC Edge hardening guidelines and related Edge Baseline guidance. [^1][^2]

Notes:
- The Edge hardening guidance aligns with ACSC and Microsoft Edge Security Baseline requirements. See the linked sources for policy details and the exact settings included in the baseline. [^1][^2]
