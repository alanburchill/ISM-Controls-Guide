## Summary

Patches, updates, or other vendor mitigations for vulnerabilities in operating systems of workstations, non-internet-facing servers, and non-internet-facing network devices must be applied within 48 hours of release when vulnerabilities are assessed as critical or exploits exist[^1]. Push critical OS patches within 48 hours using Intune-enabled Windows Autopatch with expedited quality updates; enable hotpatching to apply security updates as content is installed[^2]. Manage deployment through Windows Autopatch groups and update rings to control content assignment and rollout timing[^3].

## Implementation Steps

### Expedited OS patches via Quality updates (Intune)

1. Create a Quality updates for Windows 10 and later profile, under Devices > Windows > Quality updates for Windows 10 and later (Preview).[^1]

2. Provide a name. It's suggested that the name of the policy aligns to the quality update version being expedited for ease of reference.[^1]

3. Define the quality updates that Windows Update for Business expedites the installation of if the device Operating System version is less than. Not provided in source documentation.[^1]

4. Define the number of days until a restart of the device is enforced.[^1]

5. Assign the profile to a group containing all applicable Windows devices.[^1]

> Note: If the number of days to wait before a restart is enforced is set to 0, the device will immediately restart upon receiving the update. The user won't receive the option to delay the reboot.[^1]

### Start using Windows Autopatch with Intune

1. Before deploying updates with Windows Autopatch, ensure you meet the prerequisites. Use either Microsoft Intune or Microsoft Graph to manage updates with Windows Autopatch.[^2]

2. Use Microsoft Intune for Windows Autopatch. Microsoft Intune provides a full-service management suite for Windows devices. Windows Autopatch is embedded natively in that console.[^2]

3. Patch compliance and velocity. Windows Autopatch aims to update 95% of devices by their target compliance date. That date is calculated based on when the content is offered and when the client is configured to finish the installation. Configure those settings in Intune using a Windows Autopatch group or Update Ring policy. To get secure as fast as possible, enable hotpatching on your devices. Full security updates are applied as soon as the content is installed, instead of waiting for a restart. Hotpatching often gets devices up to date days sooner.[^2]

4. Content controls. Windows Autopatch lets you control which Windows updates get deployed to your devices. For each content type, you can choose to either deploy those updates automatically or require manual approval. Once content is approved for deployment, it’s best practice to roll it out gradually to detect issues early. The easiest way to set up a safe rollout and configure the approval strategy for a group of devices is to create a Windows Autopatch group. They help you do three things: 1) distribute devices into Microsoft Entra groups, 2) configure your approval strategy for different content types, and 3) configure your rollout schedule for each ring. Alternatively, you can create individual policies for each content type: 1) Windows quality updates, 2) Windows feature updates, 3) Driver and firmware updates, 4) Update rings, 5) Microsoft Edge updates.[^2]

5. Create an Autopatch group to manage deployment rings and content. See the steps for creating an Autopatch group below. [^3]

6. Update reporting. Use the Autopatch reporting capabilities to monitor deployment progress. [Footnote reference not required here if not present in source excerpt.]

7. For granular setup, configure groups and update policies as needed using the Autopatch interface. See the group configuration steps in the official guidance. [^3]

### Create and manage Windows Autopatch groups

1. Create an Autopatch group and configure deployment rings. In the Dynamic group distribution column, select the desired deployment ring checkbox. Then:
   - 7.2.1 Enter the percentage of devices that should be added from the Microsoft Entra groups selected in step 9. The percentage calculation for devices must equal 100%.
   - 7.2.2 Select Apply default dynamic group distribution to use the default values.[^3]

2. In the Assigned group column, select Add group to ring to add an existing Microsoft Entra group to any of the defined deployment rings. The Test and Last deployment rings only support Assigned group distribution. These deployment rings don't support Dynamic distribution.[^3]

3. Select Next: Update types. Select the types of updates you want Windows Autopatch to create policies for. You can select:
   - 9.1 Quality updates
   - 9.2 Windows feature updates
   - 9.3 Driver updates
   - 9.4 Microsoft 365 updates
   - 9.5 Microsoft Edge updates[^3]

4. Select Next: Deployment settings. If you selected quality updates and Microsoft 365 apps updates in Step 9, these updates are deployed automatically. Use the dropdown menu to select:
   - 10.1 The target version for feature updates
   - 10.2 The approval method for driver updates
   - 10.3 The channel for Microsoft Edge updates[^3]

5. Select Next: Release schedules. In this page, select one of the release schedule presets:
   - 11.1 Information worker
   - 11.2 Shared device
   - 11.3 Kiosks and billboards
   - 11.4 Reboot-sensitive devices[^3]

6. The Windows update installation, reboot, and notification behavior setting is based on the selected release schedule preset. You can:
   - 12.1 Edit the deferrals, deadlines, grace periods as needed
   - 12.2 Edit the deployment rings as necessary[^3]
