## Summary

LSA protection is enabled by default on Windows 11, version 22H2 and later; ensure devices meet the policy criteria to run LSASS as a protected process through the **ConfigureLsaProtectedProcess** policy CSP (EnabledWithUEFILock or EnabledWithoutUEFILock)[^1][^2]. Verify LSA protection status via Event Viewer by inspecting Windows Logs/System for Credential Guard events related to LsaIso.exe (Event IDs 13-17)[^3].

## Design Decision

Use **Windows 11** to (1) configure **ConfigureLsaProtectedProcess** and (2) deploy **ScriptName.ps1** via **Intune Settings Catalog policy**.

> [!NOTE]
> LSA protection is enabled by default on Windows 11 22H2+ devices. Event Viewer verification confirms Credential Guard is active.

## Prerequisites

### Dependencies
- **Windows 11, version 22H2** or later must be running on client devices.[^1]
- **LSA protection** is enabled by default on all devices to help safeguard credentials. For new installations, it activates immediately; for upgrades, it becomes active after a five-day evaluation period followed by a system reboot.[^2]
- If the policy is not configured, LSA will run as a protected process on clean installed, **HVCI capable** client SKUs.[^2]

## Implementation Steps

### LSA protection is enabled by default on Windows 11 version 22H2+

1. On client devices running **Windows 11 version 22H2** and later, **LSA protection** is enabled by default.[^1]

2. Criteria to allow this behavior:
   - If no policy is configured for **ConfigureLsaProtectedProcess** and there is no existing registry setting for LSA protection, **LSA** runs as a protected process by default on clean installed, **HVCI capable** client SKUs.[^2]
   - For upgrade scenarios, LSA protection becomes active after a five-day evaluation period followed by a system reboot.[^1]

3. Notes:
   - Default behavior is described in enterprise guidance and reflects Windows 11 22H2+ alignment with Credential Guard and LSA protection features.[^1]

### Verify LSA protection using Event Viewer

1. Open Event Viewer (eventvwr.exe). Go to Windows Logs -> System and filter by the event source for Credential Guard events (WinInit related). Look for the following events:
   - Event ID 13: Credential Guard (LsaIso.exe) was started and will protect LSA credentials.[^3]
   - Event ID 14: Credential Guard (LsaIso.exe) configuration: indicates whether Credential Guard is configured to run. Values reflect configuration state.[^3]
   - Event IDs 15–17: Additional onboarding or status messages related to Credential Guard configuration or startup issues.[^3]

2. Interpretation:
   - If you see Event ID 13 indicating Credential Guard started, and Event ID 14 showing a configured state, LSA protection is active.[^3]

3. Validation note:
   - Regularly review these events to confirm ongoing protection status as devices are enrolled or updated.[^3]

### Configure LSA Protected Process policy using Settings Catalog

1. Create a Settings Catalog policy for device configuration.[^2]

2. Search for the policy setting: **ConfigureLsaProtectedProcess** and set its value to the desired state. The mapping is:
   - 0 = Disabled
   - 1 = Enabled with UEFI lock
   - 2 = Enabled without UEFI lock

3. Deploy the policy to the target devices or groups.[^2]

4. If required, verify the policy application by checking the registry or policy state after installation. Restart may be required for changes to take effect.[^2]

| Setting | Value |
| ------- | ----- |
| ConfigureLsaProtectedProcess | 0, 1, or 2 (0 = Disabled; 1 = Enabled with UEFI lock; 2 = Enabled without UEFI lock) |
