## Summary

Configure **Conditional Access policy** to block cloud administrators unless they originate from a trusted known IP address range, leveraging **Microsoft Entra ID** and device compliance to enforce secure admin access.[^1]

[^1]: [Deploying a privileged access solution - Privileged access - Microsoft Learn](https://learn.microsoft.com/en-us/security/privileged-access-workstations/privileged-access-deployment)

## Design Decision

Use **Microsoft Entra Conditional Access** to configure a policy that blocks cloud administrators unless they come from known trusted IP address ranges, and to deploy **ScriptName.ps1** via **Microsoft Entra admin center**.

> [!NOTE]
> Deploying **ScriptName.ps1** enforces cloud administrator access restrictions to known IP ranges.

## Prerequisites

### Permissions/Roles
- Create a **user group** for privileged accounts that will be governed by the Conditional Access policy. [^1]
- Include an **emergency break-glass** account in the group or designate an **emergency access account** that can bypass the Conditional Access policy. [^1]
- Best practice: Exclude **emergency access accounts** from the policy. [^1]

### Dependencies
- A **Microsoft Entra Conditional Access** policy to restrict cloud administrator access to compliant devices. [^1]
- Devices must be enrolled in **Microsoft Intune** and be managed by **Microsoft Defender for Endpoint** to be considered compliant; devices must present a specific device attribute value. [^1]
- Enforce **MFA** for sign-in to cloud applications as part of the policy requirements. [^1]
- Block legacy authentication protocols in the environment. [^1]

[^1]: [Deploying a privileged access solution - Privileged access | Microsoft Learn](https://learn.microsoft.com/en-us/security/privileged-access-workstations/privileged-access-deployment)

## Implementation Steps

### Configure Conditional Access Policy in Entra ID Console

1. Identify and verify the group that includes cloud administrators. Include a separate emergency break-glass group for exceptions.[^1]

2. Create a new **Conditional Access policy** that targets the cloud administrators group for cloud management apps. The policy should enforce access only from trusted IP address ranges and require MFA with a compliant device. Exclude the emergency break-glass group from this policy.[^1]

3. Deploy and test the policy. Validate that sign-ins from trusted IP ranges succeed with MFA and device compliance, and sign-ins from untrusted ranges are blocked.[^1]

| Setting | Value |
| ------- | ----- |
| Cloud apps | All cloud management interfaces |
| Assign to | Cloud Administrators group |
| Locations | Trusted IP address ranges |
| Grant access with | MFA and compliant device |
| Exclude | Emergency BreakGlass group |

[^1]: [Deploying a privileged access solution - Privileged access](https://learn.microsoft.com/en-us/security/privileged-access-workstations/privileged-access-deployment)

### Maintain Emergency Access and Break-Glass Procedures

1. Establish and document an Emergency BreakGlass process. Ensure emergency accounts are excluded from the Conditional Access policy.[^1]

2. Regularly review the BreakGlass group membership and access controls. Confirm procedures for temporary, time-bound access when required.[^1]

3. Audit and document all emergency access activity to preserve an auditable trail for regulatory and governance purposes.[^1]
