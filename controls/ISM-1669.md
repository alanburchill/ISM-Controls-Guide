## Summary

The control blocks **Office applications from injecting code into other processes** to mitigate code-injection risks from Office components. This is implemented by enabling the ASR rule via Intune to block Office apps from injecting code into other processes. [^1][^2]

## Design Decision

> [!NOTE]
> The **Block Office applications from injecting code into other processes** ASR rule will be implemented via **Intune** and deployed as an **Endpoint security Attack Surface Reduction policy** to block Office apps from injecting code into other processes. It will block code injection by Office apps across managed devices.

## Implementation Steps

### Enable ASR rule to block Office apps from injecting code into other processes via Intune

- Block Office applications from injecting code into other processes has been Not configured by default; Windows default is off. [^1]

1. Open the Microsoft Intune console and navigate to **Endpoint Security** > **Attack surface reduction**. [^2]
2. Create a new policy or modify an existing one. For a new policy, set the **Profile type** to **Attack surface reduction rules**. [^2]
3. In the **Configuration settings** pane, select **Attack Surface Reduction** and then set the policy for the rule **Block Office applications from injecting code into other processes**. [^3]
4. Optionally configure exclusions under:
   - **List of additional folders that need to be protected**
   - **List of apps that have access to protected folders**
   - **Exclude files and paths from Attack surface reduction rules**
   and add the necessary files or folders. [^3]
5. Save the policy (or complete the creation flow). [^2]
6. Restart Microsoft 365 Apps (Office) for changes to take effect. [^3]

> Note: This ASR rule blocks code injection attempts by Office apps into other processes and requires a restart of Office applications for changes to take effect. [^3] [^1]
