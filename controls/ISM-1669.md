## Summary

Configure **Block Office applications from injecting code into other processes** via Intune and deploy **ScriptName.ps1** using **Intune deployment**.[^1][^2]

[^1]: [Intune endpoint security Attack surface reduction settings](https://learn.microsoft.com/en-us/intune/intune-service/protect/endpoint-security-asr-profile-settings)
[^2]: [Settings you can manage with Intune Endpoint Protection profiles for Windows devices](https://learn.microsoft.com/en-us/intune/intune-service/protect/endpoint-protection-windows-10)

## Design Decision

Use **Intune** to (1) configure **Block Office applications from injecting code into other processes** and (2) deploy **BlockOfficeASR.ps1** via **Intune**.

> [!NOTE]
> Deploying BlockOfficeASR.ps1 also enforces blocking Office apps from injecting code into other processes.

## Prerequisites

No specific prerequisites identified in source documentation.

## Implementation Steps

### Configure ASR Rule Using Settings Catalog

1. Create a new **Settings Catalog** policy.[^2]
2. Search for **Block Office applications from injecting into other processes** and configure it to **Block**.[^2]

| Setting | Value |
| ------- | ----- |
| Block Office applications from injecting into other processes | Block |

3. Deploy the policy to target devices or users.[^2]

### Configure ASR Rule Using Security Baseline (Defender for Endpoint) in Intune

1. In Intune, open the **Security Baseline** for Microsoft Defender for Endpoint and enable the setting **Block Office applications from injecting into other processes**.[^5]

2. Save and assign the baseline to the deployment group.[^5]

> [!NOTE]
> The ASR baseline includes this rule under Attack Surface Reduction Rules to block Office apps injecting into other processes.[^5]
