## Summary

A vulnerability scanner is used on a daily basis to identify missing patches and vulnerabilities across online services[^1]. Monitor the Microsoft 365 Admin Portal "Service Health" to watch for service vulnerability announcements[^2].

## Prerequisites

### Licensing
- Defender vulnerability scanning requires the appropriate Defender licensing:
  - Agentless vulnerability scanning requires **Defender for Servers Plan 2** or the **Defender for Cloud CSPM** plan. [^10]
  - Agent-based vulnerability scanning requires **Defender for Servers Plan 1** or **Plan 2**. [^10]

### Permissions/Roles
- Deploying the vulnerability scanner requires **Owner** permissions at the resource group level. [^10]
- Viewing vulnerability findings requires **Security Reader** permissions. [^10]

### Dependencies
- Endpoints must be onboarded to **Microsoft Defender for Endpoint** before using Defender Vulnerability Management. [^8][^9]
- Ensure Defender Vulnerability Management is enabled as part of **Microsoft Defender for Cloud** and that the appropriate Defender for Servers plan is active. [^6]
- Target machines must be within the supported operating systems set for vulnerability scanning. [^10]

[^6]: [Enable vulnerability scanning for machines](https://learn.microsoft.com/en-us/azure/defender-for-cloud/auto-deploy-vulnerability-assessment-defender-vulnerability-management)

[^9]: [Essential Eight patch applications](https://learn.microsoft.com/en-us/compliance/anz/e8-patch-app)
