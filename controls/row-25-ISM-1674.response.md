# Only Microsoft Office macros running from within a sandboxed environment, a Trusted Location or that are digitally signed by a trusted publisher are allowed to execute. (ISM-1674)

## Summary

Microsoft Office macros are only allowed to execute if they run in a sandboxed environment, a Trusted Location, or are digitally signed by a trusted publisher.[^1]

Implement a separate policy targeted to specific devices that allows only macros signed by trusted publishers using Intune; create a dedicated policy per publisher and deploy the corresponding trusted-publisher certificates.[^2][^9][^6]

Exclude policy members from other macro-blocking policies to avoid conflicts in policy settings. [^2]

## Design Decision

> [!NOTE] A separate Intune policy will be created, targeted to specific devices, to allow only macros signed by trusted publishers. Members of this policy will be excluded from other macro-blocking policies to avoid conflicts.

## Prerequisites

### Dependencies
1. Intune-based macro hardening configurations can be configured via Intune. [^1]
2. The Trusted Publishers certificate can be deployed to devices using Group Policy to enable macro signing trust. [^2]
3. If Group Policy is not used, distribute the Trusted Publishers certificate manually or by a script using certutil. [^3]

## Implementation Steps

### Separate Intune policy for macros signed by trusted publishers

1. Identify devices and users with a demonstrated business requirement to run Microsoft Office macros. Target these devices with a dedicated policy set. This approach aligns with ASD guidance that macro execution should be restricted to trusted contexts, including digitally signed macros[^1].

2. For each trusted publisher, create a dedicated Trusted Publisher policy in Intune and import the publisher’s public code-signing certificate into the Trusted Publishers store. This supports per-publisher control and simplifies deployment[^2]. See guidance for adding trusted publishers via Intune for certificate deployment details[^4].

3. For each Trusted Publisher, create a separate macro-execution policy that enforces:
   - Disable all macros except digitally signed macros; and
   - Require macros to be signed by a trusted publisher.
   This targeted policy ensures only macros signed by the specified trusted publisher can run on the enrolled devices[^2]. Use the recommended macro signing approach (V3 signatures) when signing macros[^2].

4. Deploy the Trusted Publisher certificate policy and the corresponding macro-execution policy to the same device group(s) to ensure consistency between certificate trust and macro execution rules[^3].

5. Ensure that members of this separate policy are excluded from other macro-blocking policies to avoid conflicts in policy settings. This separation prevents overlapping rules from causing unintended macro behavior[^1][^9].

6. Reference remote certificate deployment scripts or guidance as needed:
   - Intune certificate deployment guidance for Trusted Publishers is available here: [Intune: Adding a Certificate to Trusted Publishers using Intune](https://techcommunity.microsoft.com/t5/intune-customer-success/adding-a-certificate-to-trusted-publishers-using-microsoft/ba-p/1974488#:%7E:text=To%20add%20a%20certificate%20to%20the%20Trusted%20Publishers,a%20new%2C%20custom%20Windows%2010%20device%20configuration%20profile)[^4].

Notes
- The policy approach mirrors the core requirements for macro protection: macros are blocked by default and allowed only when signed by a trusted publisher or running in trusted contexts[^1][^9].
- Macros from the internet remain blocked by default unless explicitly configured to signed trusted publishers, per Microsoft guidance[^9].
