## Design Decision

Use **Intune** to (1) configure **Office hardening policies** and (2) deploy **ScriptName.ps1** via **Intune deployment**.

> [!NOTE]
> Deploying **ScriptName.ps1** also disables **Other Feature**.

## Prerequisites

- **Licensing:** Microsoft Intune Plan 1 licensing at minimum is required for Intune-based configuration deployment. This licensing is typically included in Microsoft 365 E3 or higher subscriptions.[^6]

- **Permissions/Roles:** Access to the Microsoft Intune admin center with the ability to create and deploy policy settings using the Settings Catalog or Administrative Templates. To start, go to Devices > Configuration profiles > Create profile; Platform: Windows 10 and later; Profile type: choose the appropriate policy type.[^5]

- **Dependencies:** Intune-enabled deployment of Office hardening policies, using the Microsoft 365 Apps for Enterprise security baseline available in Intune to manage Office settings.[^1]

## Implementation Steps

### Configure Office hardening using Settings Catalog

1. Create a new **Settings Catalog** policy in Intune to enforce Office hardening settings[^5][^4].  
2. Configure the catalog with the **Office security baseline** settings as defined by the Microsoft 365 Apps for Enterprise baseline[^1].  
3. Deploy the policy to target devices or users[^1].

### Deploy Office hardening using Security Baseline in Intune

1. Create a security baseline for Microsoft 365 Apps for Enterprise in Intune to enforce Office hardening settings[^1].  
2. Ensure the baseline is updated to the current version when available and deployed to the appropriate groups[^1].  
3. Verify that policies deployed via Intune cannot be changed by standard users and that enforcement remains in place[^4].  
4. Enhance protection by configuring macro hardening as part of the baseline, such as blocking macros from running from the Internet[^5].

> [!NOTE]
> Policies deployed via Intune cannot be changed by standard users; enforcement remains in place once deployed[^4].
