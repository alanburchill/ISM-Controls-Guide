# Patches, updates or other vendor mitigations for vulnerabilities in online services are applied within two weeks of release when vulnerabilities are assessed as non-critical by vendors and no working exploits exist.

## Summary

Configure **Windows Autopatch** via the **Intune admin portal** and enroll all workstations to receive updates. Updates are installed within two weeks of release for non-critical vulnerabilities.[^1]

[^1]: [ASD Blueprint: Windows update and patching](https://blueprint.asd.gov.au/design/endpoints/windows/configuration/windows-update-and-patching/)

## Design Decision

Use **Windows Autopatch** to (1) configure **Windows Autopatch enrollment for all workstations** and (2) deploy **AutopatchEnrollment.ps1** via **Intune**.

> [!NOTE]
> Deploying **AutopatchEnrollment.ps1** also disables the legacy patching workflow.

## Prerequisites

* **Licensing:** Intune Plan 1 licensing is required for target devices configured via Intune.[^1]
* **Permissions/Roles:** Global Administrator role is required to enable Windows Autopatch readiness assessment; minimize the number of users with Global Administrator role.[^1]
* **Dependencies:** Access to Microsoft Intune and Microsoft Entra ID to enroll devices into Windows Autopatch and to run readiness assessment.[^1]
* **Dependencies:** Admin contacts must be defined for each area of focus (Devices, Device health, Updates, Windows quality updates, Microsoft 365 Apps for enterprise updates, Microsoft Edge updates, Microsoft Teams updates).[^1]
* **Dependencies:** Device registration prerequisites must be reviewed prior to registering devices with Windows Autopatch, including adding devices to the Windows Autopatch Device Registration Microsoft Entra group.[^1]
* **Dependencies:** Windows Autopatch device types and Windows 365 Cloud PC integration prerequisites include registering devices with Autopatch and provisioning Windows 365 Cloud PCs if used.[^1]

[^1]: [Essential Eight patch operating systems](https://learn.microsoft.com/en-us/compliance/anz/e8-patch-operating-systems)

## Implementation Steps

### Enroll in Windows Autopatch using Intune admin portal

1. As a Global Administrator, open the Intune admin center and navigate to **Tenant administration** > **Windows Autopatch** > **Tenant enrollment**. Run the **Readiness assessment** to verify that settings support Autopatch enrollment.[^1]

2. In Intune, configure admin contacts for each area of focus. Add name, email, phone, and language; assign each contact to the relevant area of focus.[^1]

3. Add devices to the **Windows Autopatch Device Registration** group to enroll them into Autopatch. Autopatch will perform prerequisite checks, calculate the deployment ring distribution, assign devices to required Microsoft Entra groups, and mark devices as active for management.[^1]

### Validate and Monitor Autopatch Deployment

1. Sign into Intune. Navigate to **Reports** > **Windows Autopatch** > **Windows Quality Updates** to view the All Devices Report. The report shows:
   - Device name
   - Microsoft Entra device ID
   - Serial number
   - Deployment ring
   - Update status
   - Update sub status
   - OS version
   - OS revision
   - Intune last check-in time[^1]

2. Use the Autopatch dashboard and reporting to monitor ongoing update status and history for enrolled devices. Update status details can be exported as needed.[^1]

[^1]: [Essential Eight patch operating systems - Essential Eight](https://learn.microsoft.com/en-us/compliance/anz/e8-patch-os)
