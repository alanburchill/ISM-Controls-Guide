## Summary

Configure **Break Glass Accounts** via Microsoft Entra ID with a randomly generated password and configure a physical **FIDO2 security key** for MFA.[^1][^2]

[^1]: [Manage emergency access admin accounts - Microsoft Entra ID - Microsoft Learn](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/security-emergency-access)

[^2]: [Microsoft cloud security benchmark v2 - Privileged Access - Microsoft Learn](https://learn.microsoft.com/en-us/security/benchmark/azure/mcsb-v2-privileged-access)

## Design Decision

Use **Microsoft Entra ID** to (1) configure **break glass accounts** and (2) deploy a physical **FIDO2 security key** for MFA via emergency access provisioning.

> [!NOTE]
> Break glass accounts will use randomly generated passwords and be protected by a physical **FIDO2 security key** for MFA.

## Prerequisites

### Permissions/Roles
1. Sign in to the Microsoft Entra admin center as at least a **User Administrator**.[^1]
2. Create emergency access accounts: configure at least two cloud-only accounts (not federated) with **Global Administrator** role in Microsoft Entra ID, using descriptive names that clearly identify their purpose, ensuring accounts are not assigned to specific individuals and remain dedicated exclusively for emergency scenarios.[^2]
3. Ensure the **Global Administrator** role assignment for these emergency access accounts is active permanently rather than eligible.[^1]
4. Use strong authentication for emergency access accounts and make sure it doesn't use the same authentication methods as regular administrative accounts; consider a **FIDO2 security key** for emergency accounts.[^1]

### Dependencies
1. Individuals authorized to use emergency access accounts must utilize a designated, secure workstation or similar client computing environment, such as a Privileged Access Workstation.[^1]
2. Store credentials for emergency access accounts securely in secure locations, e.g., fireproof safes at separate sites; credentials should be long, unique, randomly generated, and configured to never expire; implement dual control with multi-person approval for retrieval.[^1]
3. Credentials for emergency access accounts must not expire and must not be included in automated cleanup due to lack of use.[^1]
4. Configure monitoring and alerting for emergency access account sign-ins and changes; use **Azure Monitor** or **Microsoft Sentinel** and document incident response procedures.[^2]
5. Create cloud-only emergency access accounts using the onmicrosoft.com domain (e.g., EmergencyAccess01, BreakGlass02) and ensure they are not federated.[^8]
6. Break glass accounts must have a randomly generated password and configured a physical **FIDO2** key for MFA.[^1][^2]

## Implementation Steps

### Create Emergency Access Accounts in Microsoft Entra ID

1. Create at least two cloud-only emergency accounts with the **Global Administrator** role in Microsoft Entra ID. Use descriptive names (e.g., EmergencyAccess01, BreakGlass02) that clearly identify their purpose. Ensure accounts are not tied to individuals and are dedicated exclusively for emergency scenarios. [^1]

2. Sign in to the Microsoft Entra admin center as a user with sufficient privileges and copy the Object ID attribute for each emergency account to enable monitoring and automation. [^1]

3. Configure these accounts as cloud-only (not federated) and ensure credentials are kept in a known secure location accessible to multiple members of the administration team, separate from employee devices. [^1]

4. In Microsoft Entra ID Privileged Identity Management (PIM), make the Global Administrator role assignment for these accounts active permanently rather than eligible, to ensure persistent emergency access. [^1]

### Configure Passwords and Dual Control for Break-Glass

1. Generate strong, randomly generated passwords of at least **32 characters** for each emergency account. Configure the credentials to never expire. Implement dual control by splitting credentials into multiple parts stored in separate secure physical locations (e.g., fireproof safes at different sites) accessible only to authorized executives, with documented retrieval procedures requiring multi-person approval. [^2]

2. Store account credentials securely in the locations described in Step 1 and ensure they are not connected to employee devices. [^1]

3. Apply phishing-resistant MFA for break-glass accounts. If normal administrator accounts use MFA with the Microsoft Authenticator app, configure the break-glass accounts to use a different method, such as a **FIDO2 security key** for MFA. [^1]

### Enable Monitoring and Alerting for Emergency Accounts

1. Configure monitoring by enabling **Azure Monitor** or **Microsoft Sentinel** to analyze Entra ID sign-in and audit logs for emergency accounts. Create real-time alerts triggered by any emergency account authentication or configuration change, and document incident response requirements for such events. [^2]

2. Review and tune alert rules regularly; ensure that sign-ins from emergency accounts trigger notifications to the security team. [^2]

### Testing and Maintenance Procedures for Break-Glass

1. Test emergency account access on a quarterly basis to verify functionality. Update credentials every **90 days** or after personnel changes affecting authorized users. Maintain written runbooks detailing the complete emergency access process for compliance and operational readiness. [^2]

2. Conduct regular drills to validate emergency access usage and ensure monitoring and alerting remain effective. Update the list of authorized individuals and ensure the designated secure workstation is available. [^1]

### Additional Considerations

- Use a designated secure workstation or **Privileged Access Workstation** when interacting with break-glass accounts. [^1][^9]

- Enable phishing-resistant authentication for break-glass accounts by using **FIDO2 security keys** or other phishing-resistant methods; align with Zero Trust guidance. [^10]
