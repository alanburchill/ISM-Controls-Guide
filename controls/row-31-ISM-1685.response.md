## Summary

Establish emergency break-glass accounts by creating at least two cloud-only Global Administrator accounts dedicated to emergency use. Configure credentials with dual control and strong randomness: generate passwords at least 32 characters long, set them to never expire, and store credential parts in separate secure locations. Require a physical FIDO2 key for MFA for break-glass access where feasible to enhance resilience during outages. Regularly test and monitor emergency accounts, updating credentials at defined intervals and maintaining runbooks for auditing and compliance. [^1][^3][^4]

## Design Decision

> [!NOTE] Break-glass accounts will use randomly generated passwords and require a physical FIDO2 key for MFA.

## Implementation Steps

### Break-glass accounts with random password and FIDO2 MFA

1. Create emergency access accounts. Configure at least two cloud-only accounts (not federated) with Global Administrator role in Microsoft Entra ID. Use descriptive names (e.g., EmergencyAccess01, BreakGlass02) that identify their purpose. Do not assign these accounts to specific individuals; keep them dedicated to emergency scenarios. [^1]

2. Secure credentials with dual control. Generate strong, randomly generated passwords of at least 32 characters and configure them to never expire. Split credentials into multiple parts and store them in separate secure physical locations, accessible only to authorized executives or security leadership. Document retrieval procedures requiring multi-person approval. [^1]

3. Configure MFA with a physical FIDO2 key. Require MFA using a physical FIDO2 key for break-glass accounts. FIDO2 tokens provide unphishable MFA and are suitable for emergency access scenarios; offline provisioning of usernames, public keys, and permissions on devices is supported. When access involves network devices, break-glass authentication can leverage FIDO2 keys stored in secure locations. For network-fabric break-glass usage, see the detailed break-glass access guidance. Example login flow using a FIDO2-enabled path may involve SSH with a jump server and FIDO2-authenticated credentials:
   ```bash
   ssh -J JumpBoxUsername@JumpBoxIp EntraUsername@FabricDeviceIP
   ```
   This demonstrates break-glass login via SSH using a FIDO2 key. [^2][^3]

4. Enable comprehensive monitoring and alerting. Configure Azure Monitor or Microsoft Sentinel to analyze Entra ID sign-in and audit logs. Create real-time alerts (email and SMS) for any emergency account authentication or configuration change. Establish incident response procedures requiring immediate security team notification and justification documentation for all emergency account usage. [^1]

5. Establish testing and maintenance procedures. Test emergency account access quarterly to verify functionality. Update credentials every 90 days or immediately after personnel changes affecting authorized users. Train authorized administrators on break-glass procedures, including credential retrieval and incident documentation. Maintain written runbooks detailing the full emergency access process for compliance and operational readiness. Conduct regular account validation drills to ensure ongoing accessibility and control effectiveness. [^1][^6]
