## Summary

Use RBAC in Microsoft Defender XDR and Sentinel to protect event logs from tampering.[^1] Centralize event logs in a Log Analytics workspace and enforce RBAC to restrict modify/delete activities.[^1] Ensure tamper protection prerequisites are met in device management contexts.[^2] Enable Protected Event Logging to encrypt event log data before writing to the logs.[^3]

[^1]: [Protect event logs from unauthorized modification and deletion (ML3)](https://learn.microsoft.com/en-us/compliance/anz/e8-admin#protect-event-logs-from-unauthorized-modification-and-deletion-ml3)
[^2]: [Prerequisites](https://learn.microsoft.com/en-us/defender-endpoint/manage-tamper-protection-intune#prerequisites)
[^3]: [Policy CSP - ADMX_EventLogging](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-eventlogging#enableprotectedeventlogging)

## Design Decision

> [!NOTE] RBAC will be implemented in Microsoft Defender XDR and Sentinel to protect event logs from tampering. Access to event logs will be restricted to authorized roles.

## Prerequisites

* **Licensing:** Intune licenses are required. [^2]

* **Permissions/Roles:** You must have appropriate permissions assigned through roles, such as Security Administrator. Log Analytics workspaces must be secured with role-based access controls. [^2][^1]

* **Dependencies:** Windows devices must be managed by Intune or Configuration Manager; Windows 10 version 1709 or later or Windows 11; Defender for Endpoint must be onboarded; Entra ID alignment: Intune and Defender for Endpoint tenants must share the same Microsoft Entra infrastructure; Security intelligence version 1.287.60.0 or later; Antimalware platform version 4.18.1906.3 or later and anti-malware engine version 1.1.15500.X or later. [^2]
