## Summary

Configure **RBAC for event log protection in Microsoft Defender XDR and Sentinel** to protect event logs from tampering.[^1]

[^1]: [Essential Eight restrict administrative privileges - Essential Eight - Microsoft Learn](https://learn.microsoft.com/en-us/compliance/anz/e8-admin)

## Design Decision

Use **RBAC** in **Microsoft Defender XDR** and **Microsoft Sentinel** to protect event logs from tampering.

> [!NOTE]
> The RBAC model restricts access to event logs to authorized roles only.

## Prerequisites

### Permissions/Roles

- Enforce **RBAC** for **Microsoft Defender XDR** and **Microsoft Sentinel** to protect event logs from tampering.[^2][^3]
- Assign appropriate RBAC roles, such as **Global Administrator** or **Security Administrator**, to manage tamper protection and log access.[^4]
- Use **Microsoft Entra ID RBAC** to protect event logs stored in **Log Analytics**.[^1][^3]

### Dependencies

- Centralize event logs in a **Log Analytics workspace**.[^1]
- Set a lock on the **Log Analytics workspace** to block deletion, purge, and retention changes.[^1]
- Enable automated exports of log data to an immutable storage solution such as **Immutable Storage for Azure Blob Storage**.[^1]
- Onboard devices to **Microsoft Defender for Endpoint**.[^4]
- Ensure devices meet OS requirements and Defender platform versions:
  - Devices must be on supported Windows or macOS versions.[^4]
  - Devices must be onboarded to **Microsoft Defender for Endpoint**.[^4]
  - Anti-malware platform version 4.18.2010.7 or later and anti-malware engine version 1.1.17600.5 or later.[^4]
- Turn on **Cloud-delivered protection**.[^4]

## Implementation Steps

### Configure RBAC for Defender XDR and Sentinel

1. Ensure you have appropriate permissions assigned (e.g., Global Administrator or Security Administrator).[^4]
2. Enable and enforce **RBAC for Defender XDR and Microsoft Sentinel** to protect event logs from tampering.[^2]
3. Configure **Entra ID RBAC** for access to event logs in Defender XDR and Sentinel.[^3]

### Centralize Logs in Log Analytics and Enforce Access Controls

1. Centralize event logs in a **Log Analytics workspace** within Azure Monitor.[^1]
2. Protect workspace access using **Entra ID RBAC**.[^3]
3. Set a lock on the **Log Analytics workspace** to block data deletion and retention changes.[^1]
4. Consider automated exports of log data to an **Immutable Storage for Azure Blob Storage** storage solution.[^1]

### Harden Tamper Protection and Access Controls

1. Enable **tamper protection** in the Microsoft Defender portal. Go to the Defender portal, sign in, and navigate to Settings > Endpoints > Advanced features > Tamper protection.[^4]
2. Note that tamper protection restricts tamper-protected settings to secure defaults and changes to these settings are ignored.[^4]
3. Use management tools such as **Intune** or **Microsoft Defender Endpoint** to exclude devices from tamper protection if required by policy.[^4]

### Windows Event Forwarding Considerations

1. Windows Event Forwarding is a passive mechanism and cannot modify log sizes, channels, permissions, or audit policies; it only queries existing events for intrusion detection.[^5]
