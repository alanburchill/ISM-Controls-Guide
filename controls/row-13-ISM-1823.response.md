## Summary

Deploy Intune-based hardening policies to ensure Office security settings cannot be changed by users[^1].

Use the Microsoft 365 Apps for Enterprise security baseline in Intune (version 2306) and enforce it via the Settings Catalog to standardize lockdown settings across devices[^4][^6].

Implement Attack Surface Reduction policies and configure Application Guard for Office as part of the baseline to block unsafe Office behaviors and prevent macro execution[^5][^7].

## Design Decision

> [!NOTE] Office security settings will be enforced via Intune Office hardening policies to prevent users from changing security configurations.

## Prerequisites

* **Dependencies:** Microsoft Intune is required to configure and deploy policy settings (Settings Catalog or Administrative Templates) to Windows 10 and later devices. Entra ID groups are used to target device configurations deployed via Intune. [^1][^9]

## Implementation Steps

### Deploy Intune Office hardening policies

1. Open the Microsoft Intune admin center and create a Windows 10+ device configuration profile using the Settings Catalog. This approach leverages policy tooling to configure and deploy settings to devices. [^1][^6]

2. In the policy, add the following Office hardening settings:
   - Block macros from running in Office files from the Internet. [^4]
   - Block Office applications from creating executable content. [^5]
   - Block all Office applications from creating child processes. [^5]
   - Block Win32 API calls from Office macros. [^5]

3. Save the policy and assign it to the target device or user groups. The policy applies on the next device check-in. [^6]

4. Optional: Create an Attack Surface Reduction (ASR) policy in Intune and configure the same Office hardening rules to strengthen enforcement at the OS level. [^5]

5. Validate policy deployment using Defender for Office 365 Configuration Analyzer to confirm the policies are applied and enforced. [^3]

6. Monitor policy status in Intune (Device Profile Monitor) and verify updates are applied as devices check for configuration updates. [^6]
