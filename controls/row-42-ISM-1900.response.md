# A vulnerability scanner is used at least fortnightly to identify missing patches or updates for vulnerabilities in firmware.

## Summary

Onboard devices to **Microsoft Defender for Endpoint** and monitor vulnerabilities via the **Microsoft Defender** security portal report under **Exposure management** > **Vulnerabilities**.[^1][^2]

[^1]: [Essential Eight patch operating systems](https://learn.microsoft.com/en-us/compliance/anz/e8-patch-os)
[^2]: [Firmware and hardware assessment - Microsoft Defender Vulnerability Management](https://learn.microsoft.com/en-us/defender-vulnerability-management/tvm-hardware-and-firmware)

## Design Decision

Use **Microsoft Defender for Endpoint** to onboard devices and enable vulnerability reporting via the **Microsoft Defender** security portal report under **Exposure management** > **Vulnerabilities**.

> [!NOTE]
> Onboarding devices with **Microsoft Defender for Endpoint** enables the exposure management vulnerabilities view in the Defender portal.

## Prerequisites

- **Licensing:** If the implementation uses **Intune** to configure devices (for example, deploying scripts, Settings Catalog policies, or configuration profiles), device licensing must include **Microsoft Intune Plan 1** at minimum. This is typically included in **Microsoft 365 E3** or higher subscriptions. The licensing requirement applies if Intune is referenced in the implementation approach.[^1]

- **Permissions/Roles:** 
  - Endpoints must be onboarded to **Microsoft Defender for Endpoint** before vulnerability management can assess devices.[^1]
  - Onboarding requires sufficient permissions; the onboarding process may fail with a message stating the required permission is **Manage security settings in Defender** when adding a new agent.[^1]

- **Dependencies:** 
  - An automated method of asset discovery must be used at least fortnightly to support vulnerability scanning activities.[^2]
  - A vulnerability scanner must be deployed and configured with an up-to-date vulnerability database.[^2]
  - Devices must be onboarded to **Microsoft Defender for Endpoint** to enable **Microsoft Defender Vulnerability Management** monitoring of risk across devices.[^1]
  - If remediation through **Intune** is planned, the **Microsoft Intune** connection must be enabled in the Defender portal before creating remediation tasks.[^1]

## Implementation Steps

### Onboard devices to Microsoft Defender for Endpoint

1. Prerequisite: Onboard endpoints to **Microsoft Defender for Endpoint**. [^1]

2. Create a new **Windows Configuration Profile** with a value of type Template > **Microsoft Defender for Endpoint** for desktop devices running Windows 10 or later. [^3]

3. Configure the profile to enable telemetry: set **Telemetry reporting frequency** to **Enable**. [^3]

4. Assign the profile to a group containing all applicable Windows devices. [^3]

### View vulnerabilities in the Defender security portal report

1. Open the Defender security portal and go to **Exposure management** > **Vulnerability management** > Inventories. [^1]

2. Review the vulnerabilities listed for each device and the associated exposed devices. [^1]

3. To see details on a specific weakness, select a CVE to open a flyout with more information. [^1]
