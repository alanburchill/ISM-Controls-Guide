## Summary

Configure **Block Win32 API calls from Office macros** via Intune and deploy **ScriptName.ps1** using Intune policy deployment.[^1]

[^1]: [Intune endpoint security Attack surface reduction settings - Microsoft Intune - Microsoft Learn](https://learn.microsoft.com/en-us/intune/intune-service/protect/endpoint-security-asr-profile-settings)

## Design Decision

Use **Intune** to (1) configure **Block Win32 API calls from Office macros** and (2) deploy **ScriptName.ps1** via **Intune policy deployment**.

> [!NOTE]
> Deploying **ScriptName.ps1** also disables **Other Feature**.

## Prerequisites

### Dependencies
- Access to the Microsoft Intune admin console to manage Attack Surface Reduction (ASR) policy. [^1]
- The ability to import a policy under Devices > Windows > Configuration profiles > Create > Import Policy. [^1]
- A locally saved policy file named the All Macros Disabled policy, saved on the device before import. [^1]
- A dedicated group named **Allow macro execution - Trusted Publisher** to exclude from the All Macros Disabled policy. [^1]
- The **All Office Users** group exists and is the target for the All Macros Disabled policy. [^1]
- The ASR rule to block Win32 API calls from Office macros is configured via Intune as described in the ASR settings. [^2]

[^1]: [Essential Eight configure Microsoft Office macro settings - Essential Eight](https://learn.microsoft.com/en-us/compliance/anz/e8-macro)
[^2]: [Intune endpoint security Attack surface reduction settings - Microsoft Intune](https://learn.microsoft.com/en-us/intune/intune-service/protect/endpoint-security-asr-profile-settings)

## Implementation Steps

### Configure ASR rule via Intune Endpoint Security profile

1. In the Microsoft Intune admin center, create a new **ASR policy** (Endpoint Security > Attack Surface Reduction).[^1]

2. Configure the ASR rule **Block Win32 API calls from Office macros** to **Block**. The rule is controlled via GUID 92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7B.[^1][^3]

| Setting | Value |
| ------- | ----- |
| **Block Win32 API calls from Office macros** | **Block** |

3. Assign the policy to target devices or users (e.g., a group).[^2]

4. Validate policy application. For a safe rollout, test in audit mode first as recommended by ACSC.[^4]
