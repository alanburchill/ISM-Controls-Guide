## Summary

Enable Credential Guard via an Intune device configuration profile to protect credentials by isolating secrets using virtualization-based security[^1]. Configure delegation of credentials on clients with Intune by enabling Restrict delegation of credentials to remote servers and selecting either Restrict Credential Delegation or Require Remote Credential Guard[^2]. Implement this configuration via an Intune Settings Catalog policy under Administrative Templates > System > Credentials Delegation and assign it to the appropriate device group[^2]. Credential Guard is enabled by default on supported Windows versions when requirements are met, and Intune-based deployment supports centralized management[^3].

## Design Decision

> [!NOTE] Credential Guard will be enabled via an Intune device configuration profile.

## Prerequisites

* **Permissions/Roles:** Administrative roles must be segregated in line with ASD guidance on restricting administrative privileges. [^3]

* **Dependencies:** Intune/MDM configuration capabilities are required to deploy a Settings Catalog policy or a custom Policy CSP, and onboarding/configuration will be performed by Endpoint Manager. [^1][^3]

## Implementation Steps

### Enable Credential Guard via Intune device configuration profile

1. In the Intune admin center, create a Settings Catalog policy and configure Credential Guard delegation as described.[^1]

2. Within the policy, configure:
   - Category: Administrative Templates > System > Credentials Delegation
   - Setting name: Restrict delegation of credentials to remote servers
   - Value: Enable and in the dropdown, select one of the following:
     - Restrict Credential Delegation
     - Require Remote Credential Guard
   This enforces how credentials can be delegated to remote servers.[^1]

3. Assign the policy to a group that contains the devices or users to configure.[^1]

4. Alternatively, configure devices using a custom policy with the Policy CSP.[^1]

> [!NOTE] Credential Guard default enablement on Windows 11, 22H2 and Windows Server 2025: Credential Guard and VBS are enabled by default on devices that meet the requirements; default enablement is without UEFI Lock. If needed, disable can be managed per policy.[^2]
